# AWS 構成仕様（安全なAI支援開発環境）

本仕様は、安全なAI支援開発環境を構築・運用するためのAWS構成と管理方針を定める。目的は、学生がAIコーディング支援を安全に利用できる体制を整えることであり、単なる利便性の追求ではない。

## 目的

- 学生ごとの作業空間を分離し、相互干渉や情報漏えいを防ぐ。
- AIコーディング支援を安全に利用できる運用ルールを整備する。
- 権限管理と監査ログにより、運用リスクを低減する。

## 推奨構成

- AWS EC2上に共通の開発サーバーを1台用意する。
- GPUは使用しない。
- 学生ごとにLinuxアカウントを分ける。
- 学生ごとに作業用コンテナを分ける。
- VS Code Remote SSHでEC2へ接続する。
- 開発作業は原則としてコンテナ内で行う。
- Claude Code等のAIコーディング支援は、コンテナ内で利用する。
- APIキーは教員側で一元管理し、個人配布はしない。

## 管理体制

- 教員が全体管理者として管理権限を持つ。
- 学生管理者を1名置く。
- 学生管理者には日常運用に必要な範囲の管理権限のみを付与する。
- 一般学生にはsudo権限を付与しない。
- 脆弱性に対する走査ログを残す。

## 最低限必要な安全対策

- SSHは鍵認証を必須とする。
- 各学生のホームディレクトリは他学生から読めないようにする。
- APIキー、SSH秘密鍵、トークン等をGitHubや共有場所に置かない。
- Docker socket等、root相当の権限につながるものを一般学生に触らせない。
- AIエージェントの提案するコマンドを無確認で実行しない。
- 外部サービスや第三者のサーバーに対するスキャン、攻撃的通信、過剰アクセスは禁止する。

## 運用ルール（概要）

- アカウント発行・削除、コンテナ作成・削除は教員または学生管理者が実施する。
- APIキーは教員側で保管し、コンテナ内で必要最小限の範囲で利用する。
- 脆弱性走査のログは所定の保存期間を設けて保管する。
- 学生の作業データは学生自身のコンテナとホームディレクトリに限定する。

## 監査・ログ

- SSH接続と権限昇格の試行は監査対象とし、必要に応じてログを確認する。
- 脆弱性走査の実施履歴を記録し、過剰アクセスの兆候を確認できるようにする。

## 期待される効果

- 学生ごとの作業分離と権限制御により、情報漏えいと権限乱用を防止する。
- AI支援の利用を統制し、APIキーの漏えいリスクを低減する。
- 監査ログにより、不適切な操作や安全上の問題を早期に検知できる。
