## 12. 開発・テスト方針

### 12.1 リポジトリ構成

本プロジェクトは単一の GitHub リポジトリで管理する。履修要項データ(`curricula/**/*.yaml`)と開講年度ファイル(`offerings/<開講年度>/**/*.yaml`)も同一リポジトリ内に置く(§4.4.2)。

将来、履修要項データを別サービスから参照する必要が生じた場合のみ、別リポジトリへの分離を再検討する。

### 12.2 CI

CI は置かない。履修要項データ(`curricula/`・`offerings/`)のスキーマと整合性は、backend の起動時検査(§4.4.3)で確かめる。データに誤りがあれば起動に失敗する。

### 12.3 テスト

- **backend(ユニット)**: `pytest`(`backend/tests/`)。モデル(vllm)と api-clean はモックし、実機を呼ばない。API の応答、履修要項のロード・マージ・要件充足判定、スキーマの検証を対象とする
- **backend(実機)**: `backend/scripts/smoke_*.py` を手で実行し、vllm・api-clean との疎通と、チャット・履修提案の実際の出力を確認する。**pytest の対象外とする。** 実機の応答は非決定的で、1回に数分かかるためである(§6.3.1)。LLM の出力の質は自動テストでは押さえられず、プロンプトの規則(§7.2.1、§7.3.1、§7.4.1)についても単体テストで確かめるのは規則がモデルへ渡ることまでとする
- **frontend**: 未整備(コンポーネントテストは Vitest + Testing Library を想定)。PDF解析は `frontend/scripts/parse_grade_report_local.mjs` で手元の成績表サンプルに対して確認する

### 12.4 開発環境

本プロジェクトの開発環境・開発ツールの詳細は、本書の対象外とし、別ドキュメントで管理する。
